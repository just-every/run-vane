# Ask a question in plain English

Questions are off until the owner turns them on. The deployment also needs a model provider: set `AI_ENABLED=true`, `AI_MODEL`, `AI_API_KEY` and, for an OpenAI-compatible host other than OpenAI, `AI_BASE_URL` as Worker variables and secrets. Without them the Ask page says questions cannot be answered, and nothing leaves Vane.

The owner opens **Ask** in a site, chooses **On** and saves; the choice is audited and applies to that site only. Owners, administrators and team members with access to the site then type a question such as "Which campaigns brought paying customers from Texas this month?".

What leaves Vane is the question text, Vane's own list of metrics, breakdowns, filter operators and periods, the site's goal names, its time zone and today's date. No stored Vane analytics figure, visitor field, page value or identifier is sent; personal details typed into the question are the named input Gap below. The model only chooses a Stats API query. Vane checks every field against the Stats API's vocabulary, refuses anything else without running it, runs the query itself and shows the answer with its exact metrics, breakdown, range, filters and `/api/v1/stats` query, so the figures equal the dashboard's and the Stats API's for that query.

An ambiguous question returns two to four choices; picking one runs its query without asking the model again. A question about people, causes or anything Vane does not collect is answered with a reason and no figures. Plans outside the closed Stats API vocabulary are refused without repair. Questions and answers are not stored by Vane. The audit history records who asked and when, without the text. At most 60 question attempts an hour are allowed for one site: refused email addresses, over-limit requests and unrunnable model replies all count. Questions with an email address are refused before reaching the provider.

The ask box warns that the text goes to the provider. **Gap: typed personal data beyond email addresses is not automatically removed.** Leave out personal or confidential details. **External Gap: the deployment provider’s retention and training terms are not established by Vane.** Provider selection and credentials belong solely to the deployment’s Base `ai` module; there is no per-site provider, retry, repair request or second-provider fallback.

Assistants use the same door through the MCP tool `ask_question` with a Stats API key for the site, sharing its owner-controlled switch and question-attempt budget. Slack and Teams question doors must inherit these rules before shipping; today their connections deliver reports only. A site archive does not carry the setting: the owner turns questions on again at the destination.

Real-model translation remains partial until a live sandbox passes. After building the Worker, `node tests/ask-journey.mjs` uses private environment variables `AI_API_KEY`, `AI_MODEL` and optional `AI_BASE_URL`. It seeds synthetic traffic and a declared purchase goal in a disposable installation, sends the shared ten questions to the actual configured model through Base `ai`, checks requested metrics, breakdowns, filters and ranges, verifies every numeric answer against its Stats API query, picks a clarification without another model request, and checks refusals and text-free audit custody. There is no scripted model in this mode. A successful run prints a receipt with its revision, model and assertions; credentials and provider response bodies are never printed. Use the fleet’s private environment wrapper and heavy slot when running it on the shared Mac. A passing receipt establishes translation and query parity, not provider retention or training terms.
