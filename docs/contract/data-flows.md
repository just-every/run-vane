# Declared data flows

Every outbound flow an installation can make, moved from CONTRACT.md's "Declared data flows" section and clause bodies in the 28 October 2026 contract cleanup. `PRIVACY-005` and door rule D-3 govern them.

The owner's own website is not an integration, so the check has no `seed.json` externals entry, and it is listed under Declared data flows (`PRIVACY-005`).

The other outbound flow is Verify installation (`INSTALL-001`), listed under Declared data flows: a GET for the registered origin's public homepage (up to five redirects) that carries no visitor data and stores only the pass and fail result; the owner's own website is not an integration, so it has no `seed.json` externals entry. The one extension is the explicit owner- or administrator-started sitemap scan (`IMPORT-008`): only the registered origin’s robots.txt-listed or /sitemap.xml sitemaps and the same-origin pages they list, with an owner-selected page limit, honouring robots.txt disallow, no redirects or credentials, no stored bodies, only derived findings with URL and time and the scan actor and time and fetched and refused record.

(today the scheduled warehouse export, `API-002`, webhooks, `API-003`, and browser push services, `MOBILE-001`, and owner-initiated reporting analytics report reads, `IMPORT-005`, and owner-connected property-based analytics aggregate history reads, `IMPORT-002`).

It honours robots.txt disallow, refuses credentials and redirects, sends no visitor data or credentials, and stores no fetched bodies. Only derived install and capture findings with URL and time enter custody, beside a scan row recording actor, time, pages fetched and refused. This is the one sitemap extension to `PRIVACY-005`’s fetch boundary.

Google Search Console (`SEARCH-001`) is an optional owner-connected read flow under `PRIVACY-005`: fixed official Google endpoints receive OAuth codes/read-only credentials and the selected property/date range, returning aggregate query/page figures. No collected Vane visitor rows are sent. Credentials stay sealed locally and out of archives.

Property-based analytics (`IMPORT-002`) is an optional owner-connected read flow under `PRIVACY-005`: fixed official Google OAuth, Admin and Data API endpoints receive read-only credentials, the selected property and inclusive date range. They return source daily aggregates and key-event definitions. No collected Vane visitor record is sent. Credentials are sealed locally and excluded from archives.

Bing Webmaster Tools (`SEARCH-002`) is an optional owner-connected read flow under `PRIVACY-005`: only the fixed official Bing API receives its provider-required query API key and verified property/page addresses, returning redacted aggregate query/page/date figures. No collected Vane visitor rows are sent. Credentials stay sealed locally and out of archives.

First-party proxy setup (`INSTALL-006`, existing required `seed.json` external `cloudflare`) sends only explicit active-owner configuration requests to the fixed `https://api.cloudflare.com/client/v4/` API, with redirects refused. The API receives the one-use owner token, account and zone IDs, the existing installation Worker name, and the chosen hostname/path; it returns zone/Worker metadata and route or dedicated-domain resource IDs. No collected Vane visitor rows are sent. The token is transient and never saved, logged, exported or echoed; only the connected resource configuration and owner/action/time audit are retained. Other routes and existing DNS records are never overwritten. External server proxy traffic goes only to the owner’s installation with a site-scoped server credential, never to a Vane-operated service.

Tracking cut-over scan (`IMPORT-008`) is the explicit owner/admin-started extension of Verify installation: GET the registered origin’s robots.txt, its listed sitemaps or /sitemap.xml, and listed pages on that same origin. An owner-selected page limit bounds the scan. Robots disallow, credentials and redirects are refused. No cookies, authorization or visitor records are sent, no fetched body is kept, and only derived install/capture findings with URL/time plus actor/time/fetched/refused counts are stored. No seed.json integration entry is needed for the owner’s own origin.

REPORT-002 optionally sends aggregate report/alert figures and a private filtered dashboard link to owner-connected Slack channels or Teams workflows or Nook channels (Nook `NOOK-079` scoped integration token). Nook receives only aggregate figures and the private link in a message body with a stable idempotency key; its owner-entered origin follows the same EGRESS RULE. Slack receives its OAuth code and chat:write bot token only at fixed official endpoints. Teams receives POST Adaptive Cards at the owner-entered HTTPS workflow URL with no redirects, credentials in URLs refused, under API-002’s literal/name public-host rule. No visitor/person fields leave. Tokens and webhook URLs stay sealed and out of archives. Teams acceptance is acceptance by workflow, channel delivery unconfirmed. Resolved-address/pinned egress awaits the Base egress door.

Today Vane receives only page-load events from registered origins, sends only sign-in and invitation mail through the configured Base mail adapter, and declares Cloudflare as its only external in `seed.json`. Verify installation (`INSTALL-001`) sends one GET for the site's homepage at its registered origin, following up to five redirects. It carries no visitor data, keeps nothing beyond the pass or fail result it reports to the owner, and needs no `seed.json` externals entry because it reads the owner's own public page. The no-code event preview (`CONV-009`) likewise sends one GET for a page an owner or administrator names at the site's registered origins, following up to five redirects that stay on them; it carries no visitor data and keeps nothing. The scheduled warehouse export (`API-002`, `seed.json` external `warehouse`) is the first connected integration: only when the owner sets it up, the Worker sends signed PUT requests to the owner's own S3-compatible bucket at a public https endpoint, carrying each ended date's dashboard totals and event rows without any visitor hash, salt, IP address or user agent; its scope is write access to the named bucket and prefix, it receives nothing back but the upload result, and its secret key is encrypted at rest, revocable by stopping the export and excluded from archives. Webhooks (`API-003`, `seed.json` external `webhooks`) are the second: only when an owner or administrator adds an endpoint, the Worker POSTs signed JSON to that public https address carrying per-minute goal conversion counts and never a visitor-level field; it receives only the HTTP status, and the signing secret is encrypted at rest, revoked by deleting the webhook and excluded from archives. Browser push services (`MOBILE-001`, `seed.json` external `push`) are the third: only when a signed-in person turns on alerts in a browser, the Worker POSTs to that browser's push-service endpoint (a public https address the browser's vendor runs) a message encrypted for that browser (RFC 8291) and signed with the installation's VAPID key (RFC 8292), carrying an alert title, a site name and a link into the app and never a visitor-level field; it receives only the HTTP status. The VAPID private key is encrypted at rest; a subscription is deleted when its person turns alerts off, is removed from the team or the push service answers 404 or 410; keys and subscriptions are excluded from archives. Reporting analytics (`IMPORT-005`, optional `seed.json` external `matomo`) is read only when the owner initiates an import: the Worker POSTs `API.getBulkRequest` to the owner-entered public https Reporting API address, with the source site ID, selected local day, known report methods and a one-use token with view access; redirects are refused. It receives only aggregate reports and goal definitions, never visitor logs. Only sanitized dimensions, numeric measures and definitions enter import custody; the token and raw response are discarded before custody and are absent from previews, journals and archives. The owner-enabled plain-English questions (`AGENT-007`, optional `seed.json` external `models`) are the fourth: only when the owner turns questions on for a site and the deployment configures a model provider through the Base `ai` module (`AI_ENABLED`, `AI_MODEL`, `AI_API_KEY`, optional `AI_BASE_URL`), the Worker POSTs one chat request for each question to that provider’s https address, carrying the question text, Vane’s metric, breakdown, filter and period names, the site’s goal names, time zone and today’s date, and never a stored Vane analytics figure, visitor-level field, page value or identifier. Typed question text beyond email is not automatically stripped of personal data, as the ask-box notice states; deployment-provider retention and training terms remain an external Gap. It receives one JSON query plan, which Vane validates and discards after running it; Vane stores no question, reply or answer. The provider key is a deployment secret outside the database, archives and history; a rejected call is not retried and no second provider is tried. The owner-connected instrumentation GitHub source (`AGENT-001`, optional `seed.json` external `github`) is off until explicit audited consent: only fixed `https://api.github.com` endpoints receive the repository-scoped credential, repository and base and path identifiers and, after normal fix approval plus a separate explicit owner action, a script-only HTML edit returned to the same repository on a new Vane branch and draft PR. Source and deploy-diff bodies are read in memory and discarded. No analytics figure, visitor field, new collection field or raw source body enters Vane custody. The token is AES-GCM-sealed, bound to the site and connection generation, revocable by disconnect and rotation and excluded from archives; pending outbound PR authority is also excluded. Vane never updates the base branch, merges or deploys. Lost mutation responses are reconciled with reads, never automatically replayed. Each target integration is a new outbound data flow. These are Google Search Console, Google Analytics, Bing, ad platforms, Stripe, Shopify, WooCommerce, HubSpot, Slack, Microsoft Teams, warehouses, consent managers, Pane, Stall, Orbit, Pencil, Dial, Mango, Uptime, Spool, Nook, Crank, GitHub, Webflow and MCP clients. Each one ships only with its `seed.json` externals entry, its scopes, the data it sends and receives, and token custody (encrypted at rest, revocable and excluded from archives) declared in this section.

aggregate website analytics (`IMPORT-009` and `IMPORT-007`, optional `seed.json` external `plausible`) is read only on the owner’s request at the fixed official `https://plausible.io/api/v1/sites/goals`, `/api/v1/sites/custom-props` and `/api/v2/query` endpoints, without redirects. Requests send the source site ID, one-use Stats or Enterprise Sites API key and definition or aggregate queries; responses return goals, property names, aggregate revenue currencies or 14 complete overlap days of visitors, visits, pageviews, bounce rate, sources and goal counts for the owner-only parallel-run report. The comparison sends no native Vane rows, is transient and keeps neither raw source responses nor owner evidence in custody. No collected Vane visitor rows are sent. Only sanitized definition summaries enter reviewed import custody; the key and raw response never enter previews, journals, logs or archives. Dashboard ZIP import is local and carries no key.
